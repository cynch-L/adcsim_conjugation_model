## 三条记住就能讲清楚的线索

1. **为什么必须拆成六步** —— 每一步问的是不同的问题（有没有位点 / 位点开没开 / 露没露出来 /
   能不能反应 / 反应没反应 / 合起来是多少）。早期版本翻车就是把化学动力学混进几何可及性，
   两步合成一步，结论自相矛盾。
2. **为什么可信** —— 主链上只有 K 一个数是从实测锚点反推的，其余参数全部来自文献或 MD，
   且每个数都标了档位（A 必然 / B 稳健 / C 待验证）。糖链的总效率 1.0、赖氨酸整套，现在都是 C 档。
3. **为什么换偶联方式改动这么小** —— 四种方式共用同一套方程，差别只在「位点从哪来」和
   「几个 payload 抢位点」。半胱氨酸 8 个位点能算，糖链换成 2 个 N297，双载荷在连接那步加竞争，
   赖氨酸卡在「位点得靠肽图数」。

## 能力边界（讲的时候必须说）

- **能**：同一个抗体换工艺条件（TCEP 当量 / pH / 时间 / 温度）→ DAR 响应面。
- **不能**：新抗体序列的绝对 DAR（缺位点暴露度输入）。接 AlphaFold 也解决不了 ——
  铰链是天然无序区，pLDDT 低不是预测器算错，而是对象本身如此。
- **定位应写**：「结构给定下的工艺响应面 + 不确定性传播」，不是「任意抗体 → DAR」。

## 反推的两条解耦结论（2026-09-28 新增）

做「目标 DAR → 工艺条件」时，这两个问题是**分开**回答的，互不干扰：

1. **总量由第 ② 步决定（TCEP）** —— 反推 root-find 单调、可靠。`solve_tcep_eq_for_target_dar`
   投多少 payload 都不影响这条曲线：位点数定死总额。
2. **比例由第 ⑤ 步决定（投料比）** —— 新增 `solve_dual_feed_for_split`，对
   x = feed_A/(feed_A+feed_B) 二分，内部调同一个 `dual_loading_mass_balance`。
   总投料只要超过位点池，多投就不再改变比例（物料守恒已经管住了）。

## 反应速率的归属规则（新增 `estimate_k2`）

| 判断 | 结论 |
|---|---|
| 两个 payload 带同一个马来酰亚胺 | **k_A/k_B = 1.0**，不管分子长什么样。做反应的是连接子上的马来酰亚胺，不是 payload |
| 真的换了 warhead | 用 Mayr 方程比：log10(k_a/k_b) = s_N·(E_a − E_b)，E 与 s_N 取自 Mayr 免费数据库<br>https://www.cup.lmu.de/oc/mayr/DBintro.html ；硫醇根的 N/s_N 见 PMID 31560405 |
| 精度 | Mayr 自述：参考反应对之间差 ~2 倍，非参考 10–100 倍，且**不含位阻项** → 只给排序，不给精确值（C 档） |
| 千万别塞进速率的东西 | 分子大小差异 → class_factor；自身聚集 → availability(CAC)。这两处模型里已经有了，塞进 k2 就是重复计数 |
| 杠杆有多大 | 很小：参考条件下 p_c 已经顶到 p_conj=0.995，k2 翻倍看不出差别。真正敏感的是 A:B 比值（且只是比值）和 CAC 把可用浓度压到 cp50 附近的情形 |

## IMD2113（EGFR×TROP2 双抗，DXd + TLR7/8 激动剂，共享 8 个半胱氨酸）

**架构（2026-09-28 订正）**：DAR 8+8 不是「两种 payload 各占 8 个位点里的 4 个」，
而是**一个 linker 上同时带 1 个 DXd + 1 个 TLR7/8 激动剂**。
每个半胱氨酸挂 1 个这样的双头 linker → 8 个位点 × 每位点 2 个 payload = 8 DXd + 8 激动剂 = 「8+8」。

由此推论：
- **两种 payload 之间不存在竞争，也没有投料比可言**——它们被化学键固定 1:1 在同一个 linker 上。
  模型里 `dual_payload_dist` / `solve_dual_feed_for_split` 这套竞争分配**不适用于 IMD2113**，
  留给「两条不同 linker 混挂」的药（表里 KH815、IBI3020 等的 4+4 / 1+8 属于哪种架构，要逐个查证后才能套）。
- 对 IMD2113，双载荷问题**退化回普通半胱氨酸偶联**：只需把 8 个位点的 linker 数开够。
  唯一要反推的是 TCEP 当量。下表的「DAR」含义是 **linker 数（=位点占用数）**，不是 payload 总数：

实测/公开信息只有「linker DAR 8」（= payload 8+8），工艺参数一个都没公开，所以下列是**反推建议值**不是验证：

| 目标 linker DAR | TCEP 当量 @22 °C | @25 °C | @37 °C |
|---|---|---|---|
| 4.0 | 3.05 | 2.74 | 2.14 |
| 7.0 | 7.88 | 6.86 | 4.60 |
| 7.9 | 15.96 | 13.50 | 7.83 |
| 7.95（本结构上限） | 21.03 | 17.61 | 9.71 |

- 8.0 不可达：上限 = 8 × p_conj 0.995 = 7.96，加再多 TCEP 也没用。
- 温度为显性变量：同一 DAR7.9，22 °C 要 16 当量，37 °C 只要 7.8 当量。
- **新出现的风险（C 档）**：每个位点的 payload 质量约翻倍（DXd 893 + 激动剂 ≈800 ≈ 1.7 kDa/位点），
  铰链区拥挤比单载荷严重——静态放置已发现铰链区放不下多个蜷缩球（19/35 位点失败），
  双头 linker 的真实可达 linker-DAR 上限**可能低于 7.96**，需要用 MD 帧重新放置验证。

## 初筛链（2026-09-28 串起，`payload_qc.py`）

做这个的初衷是"湿实验太穷举，想在进实验室之前先排掉一批"。初筛回答四个问题，
以前四段代码各自独立、要人手工拼结果，现在合成一条链：

| 步骤 | 问什么 | 函数 | 状态 |
|---|---|---|---|
| 1 | 这个分子什么样（logP / 体积 / 反应端露不露） | `analyse()` | 原有 |
| 2 | 它在反应液里溶不溶、抱不抱团 | `clustering_report()` | 原有，需实测锚点 |
| 3 | 它塞不塞得进那 8 个半胱氨酸位点 | **`steric_check()`** | 新增（复用 `replace_collapsed.py` 的放置搜索，不重写） |
| 4 | 在这个 pH、这段时间里反应得完吗 | **`kinetics_check()`** | 新增（与主模型 `pc_from_teff` 同式，有回归测试钉住） |
| 5 | 一句话结论 | **`screen_payload()`** | 新增 |

汇总判定只有三种，其中 `measure_first` 是特意分出来的：

| 判定 | 含义 |
|---|---|
| `proceed` | 没卡住，可以上实验台 |
| `measure_first` | 没卡住，但缺一个关键读数，补上之前不能放行 |
| `not_recommended` | 有物理上的硬阻挡（塞不下 / 严重抱团 / 反应不完） |

`measure_first` 存在的理由：曾经有个分子纯结构筛查判"低风险"放行，结果在真实反应液里抱团。
那个"看着干净的低风险"是 bug 本身，不是分子的性质。没有实测锚点时现在一律判 unknown。

### 现有锚点（只有 2 条，远不够）

| payload | CAC（水） | σ | 档 | 出处 |
|---|---|---|---|---|
| vc-MMAE | 3.71e-4 M | 1.6 | B（下界，非拟合值） | CRO 实操：10% DMA、8–10 当量做到 DAR8 → ≥536 µM 可用 |
| DL012（艾日布林） | 5.71e-5 M | 9.8 | C | WO2024235127A1 实施例 3.1 |

目标是攒到 8–10 条。在此之前，初筛对陌生分子只能说"补测前不能放行"。

### 位阻这一步的已知结论（阈值 2.0 Å，重原子）

8 个位点全部放得下，最差重原子距离 1.97 Å；但同时放满 8 个时构象被迫从蜷缩退到半伸展——
这是铰链区的真实几何限制，不是算错。**只判重原子**：把氢算进去会得出假碰撞。

## 溯因反向匹配（2026-09-28 新增，`alarms.py`）

`check_all()` 是**正向**的：模型算完，告诉你哪一步可能有问题。
实验台上的问题通常是**反向**的：一批货做砸了，手里有几个读数，想问是哪一步出的毛病。

下面这块做的是反向匹配。六盏灯 = 六个能真测的现象，每个原因自带一组灯的组合（指纹）：

| 灯 | 测什么 | 怎么测 |
|---|---|---|
| 游离巯基数 | 还原后有几个巯基露出来 | Ellman |
| 实测平均 DAR | 最终挂上几个 | HIC / 完整分子量 MS |
| 剩余游离药 | 反应结束时上清里还剩多少药 | LC-MS 上清 |
| 浊度/颗粒 | 药有没有自己抱团 | 浊度计 / DLS |
| 延时能否补上 | 时间翻倍后 DAR 涨不涨 | 同批料重跑一次 |
| 高 DAR 物种 | MS 里有没有 DAR6+ 的峰 | 完整分子量 MS |

| 原因 | 巯基 | DAR | 剩药 | 浊度 | 延时 | 高DAR |
|---|---|---|---|---|---|---|
| TCEP 加少了 | 低 | 低 | 高 | 正常 | 补不上 | 无 |
| payload 抱团 | 正常 | 低 | 高 | **高** | 补不上 | 无 |
| 反应太慢 | 正常 | 低 | 高 | 正常 | **能补** | 无 |
| 位点塞不下 | 正常 | 低 | 高 | 正常 | 补不上 | 无 |
| 两种药抢位点 | 正常 | **正常** | 正常 | 正常 | 补不上 | **有** |
| 降解/断键 | 正常 | 低 | **低** | 正常 | 补不上 | 无 |

分不开的地方靠再测一项：
- 「TCEP 加少了」vs「反应太慢」→ 测巯基数
- 「反应太慢」vs「位点塞不下」→ 延长时间看能不能补
- 「位点塞不下」vs「降解/断键」→ 看药还在不在
- 「payload 抱团」vs 其他 → 看浊度

`match_failure_signature()` 输入已测的灯，返回：仍然成立的候选（按能解释多少项排序）、
被排除的原因及排除依据、以及**下一项最该测的灯**（选能把剩下候选分开的那盏）。

### 图谱管不了的三件事（写在这里是因为容易被误当成它能管）

- 抗体本身的氧化、糖型杂、聚体：它是**输入条件**不是偶联结果，靠批次质谱当输入项
- 游离巯基又氧化回去：留下的灯和「TCEP 加少了」一模一样，要靠 Ellman 隔时间取样才分得开
- 点击化学 / 酶偶联 / 糖基偶联：六个环节对不上，这套图谱不适用

这张图谱现在的定位是**待检验的假设表，不是验证过的诊断表**。指纹之间的关系来自模型结构，
还没有一批真实失败样品撞过。要变成能用的东西，得拿真实失败批次去填灯。
